# MCP bridge

`github.com/dailz1/go-agent/mcp` is a `mcpbridge` package in the root module. The official MCP SDK is compiled only into binaries that import this package. It is a client-only, tools-only bridge with manual tool-set reconciliation: callers create an official MCP transport and connect into a `tool.Registry` (dedicated or shared). The freshness/quiescence precondition is namespace-scoped: during `Connect` and `Refresh`, no concurrent external registry mutation may touch the same namespace — documentation language, with out-of-bounds collisions caught by `Registry.Apply`'s duplicate checks; a failed `Connect` unregisters its partial registrations.

`Config.Namespace` and every final `${namespace}__${remote}` name must match `^[A-Za-z0-9_-]{1,64}$`; namespaces cannot contain `__`. Discovery is per-call static with manual reconciliation: `Refresh(ctx)` re-lists and reconciles the bridge's owned set atomically via `Registry.Apply`, rewriting the owned name/wrapper tables only on success; fetch or apply failure keeps both the registry and the owned set unchanged. Names under the namespace prefix that the bridge does not own are never touched and land in the Refresh summary's conflict list instead. Auto-subscribing to list-changed is a v1 non-goal. Within the un-refreshed window, a removed remote tool still produces a hard protocol error. Multi-round-trip handling is disabled, so input-required results are one soft `v1 不支持 MCP input-required continuation` result with no retry.

Approval defaults to required for every bridge tool. `WithApprovalRequired(false)` relaxes only tools whose annotations explicitly say read-only and do not say destructive; all other tools remain approval-gated. Input schemas are projected from the SDK-decoded map through `ParameterSchema.UnmarshalJSON`; full vocabulary is typed-or-carried in name-sorted form, while duplicate keys, encounter order, and precise numeric tokens are outside the SDK decode boundary. Provider acceptance is independent from schema representability.

**SDK v1.7.0 discovery boundary:** `ClientSession.ListTools` logs and silently excludes tools with an invalid `x-mcp-header`: the annotation is on a non-string/integer/boolean property, has a non-string/empty/invalid HTTP field-name value, or duplicates a case-insensitive header value at any nesting. The bridge cannot observe or reject those rows. Server authors must fix the annotation; a future SDK option is the only v1 escape.

Text content joins with newlines. Image, audio, resource-link, and embedded-resource content gets an escaped typed Content placeholder and an indexed JSON Data envelope. `WithResultDataLimit` defaults to 1 MiB, rejects non-positive values at Connect, and checks the final cumulative encoded envelope before accepting each entry. Data is available only to live `ToolResultEvent` consumers; history and Store retain Content only. `OutputSchema`, top-level tool Title/Icons, content annotations, resource-link icons, all `_meta`, and progress notifications are intentionally dropped.

`Close` is a graceful drain: it first publishes the closing gate so new `Execute` calls fail softly and immediately, then waits for in-flight `Execute` calls to return before unregistering and closing the session. An `Execute` blocked on a hung remote call delays `Close`; cancel that call's context to break it. `Refresh` and `Close` require caller serialization — do not run them concurrently. On `Close` the bridge unregisters its still-owned names (identity-checked; user-replaced names are left in place) before closing the session. Removing a bridge while an Agent run may still look up or hold its tool handles is safe; a run that already planned the tool gets a normal result (in-flight) or a soft error (gate closed), never a session-level hard error from the shutdown itself.

Frozen v1 non-goals: agent/server mode; resources, prompts, sampling, roots, logging, and elicitation UI; OAuth policy, configuration, automatic installation, or network discovery; auto-subscribing list-changed / automatic reconciliation (manual `Refresh` and `Close` unregister ship); bridge retry/redial, per-tool timeouts, shared sessions; and root README/examples.

### Manager (multi-server bookkeeping)

`Manager` orchestrates several Bridges over one registry: `Connect`/`Disconnect`/`Refresh` per `serverID`, `Snapshot` (per-server inventory, plain copied values), and `OwnerOf(toolName)` for failure attribution. Ownership is resolved live against each bridge's identity-checked owned set — never cached — so user `Replace` takes a name out of attribution and `Refresh` is reflected on the next query. All methods are goroutine-safe and lifecycle operations serialize against each other. It is bookkeeping only: the registry carries no notion of tool origin, and `Disconnect` is subject to the `Bridge.Close` drain contract (still not hot-unplug against runs that have not reached the gate).
